# SavePoint storage

## Portable storage and durability

IndexedDB is WebView origin storage, not a file in `/sdcard/Android/data`. On Android it is stored inside the app's private WebView profile, under `app_webview/Default/IndexedDB/https_localhost_0.indexeddb.leveldb` (plus a sibling `.blob` directory for large values). For the installed debug test package, ADB can inspect it with `adb shell run-as com.cuemark.savepoint.test ls app_webview/Default/IndexedDB`; production uses `com.cuemark.savepoint` instead of the `.test` suffix. It is a LevelDB database, not one portable SQLite/JSON file, and the app should access it through IndexedDB. Startup makes a best-effort request for Chromium persistent-storage status; the tested Android WebView returned `false` from `navigator.storage.persisted()`, so this request does not guarantee protection from storage pressure. In addition to the internal Keystore-backed records, Android now keeps an encrypted per-title recovery mirror under `/sdcard/Android/data/<package>/files/CueMark/SavePoint/` (`records/*.enc`, `meta.enc`, and any legacy `state.enc`). The first full startup backfills every library record from IndexedDB in small background batches; later title changes/deletions update individual files atomically. If IndexedDB and the internal record store are empty, the app can recover titles and metadata from this mirror. Inspect the test mirror with `adb shell ls -la /sdcard/Android/data/com.cuemark.savepoint.test/files/CueMark/SavePoint`. App-specific storage survives cache clearing, but Android removes it when app data is cleared or the app is uninstalled. The selected Storage Access Framework folder is the portable database/artwork mirror; artwork blobs remain in IndexedDB and/or that selected folder. Export a `.json.gz` backup or a password-protected `.sqx` transfer file for device migration/recovery. `.sqx` uses PBKDF2-SHA-256 (310,000 iterations) to derive an AES-256-GCM key and encrypts independently authenticated chunks; do not lose the password.

Encrypted `.sqx` transfers include the full library, source links, saved details, ratings, preferences, history, and cached artwork found in IndexedDB and the selected folder. Imports remap saved image paths and restore backup preferences and activity history. Sender folder URIs are discarded because Android SAF permissions are device-local. Save the transfer through Android's Save As picker, share it directly from Settings → Backups → Export, or send the saved file from a file manager and import it on another device. Android shows export progress and completion notifications when notifications are allowed.

## Library state

The app state is `{ items, history, preferences }`. Games are stored in **IndexedDB** (`savepoint_library`: `items` for games, `meta` for preferences and history, `details` for full provider data, `images` for saved detail artwork, and `thumbs` for the bounded cover cache); only a small mirror stays in localStorage under `splitapp_savepoint_v1`.

- **Browser preview:** IndexedDB is the state store; the localStorage mirror holds preferences and history for fast startup. Saves are scoped (only changed games are written) and run in a data worker.
- **Startup:** the library is shown straight from IndexedDB; the folder database and encrypted store are reconciled in the background, and changes made while that runs win. The folder snapshot is rewritten only when it is behind the device.
- **Artwork:** covers load from the IndexedDB cache, then online, and the saved folder only fills the cache in the background.
- **Export:** Settings → Backups → Export writes Android backups through the system Save as screen (backup-before-destructive saves quietly into the configured backup folder). Browser exports load each game's saved artwork through the IndexedDB image cache and stream JSON entries into the browser Save File picker when available; other browsers download the generated JSON. JSON, TXT and CSV exports can include or omit ratings; written reviews and notes are excluded from SavePoint exports. Artwork remains stored in IndexedDB and is embedded into JSON backup entries when available.
- **Android:** `frontend/backend/app.js` still writes the full state to localStorage as a compatibility mirror. When the `EncryptedStore` plugin is available, it stores each item as an individually encrypted native record and stores history/preferences together as encrypted metadata. The same encrypted values are mirrored atomically into app-specific external files. On load, the internal native store is preferred; if it has no item records, the app reads the external mirror. Native history/preferences merge over mirror values.
- **Android folder database:** SavePoint opens directly from its app-private local store, so the library remains usable if no shared folder has been selected yet. A shared Storage Access Framework folder can be selected in Settings → Backups; its permission is remembered in Android preferences and its URI in localStorage. Once selected, the folder contains `<app-key>_database.json` and `<app-key>-db/database.json`, each with `{ items, history, preferences }`. The in-folder database takes precedence on startup, then the root compatibility database, so the same folder can restore the library after reinstalling. If neither database exists, SavePoint can rebuild the collection from `<app-key>-db/games/<item-id>/index.json` records. A dated `<app-key>-backup-YYYY-MM-DD.json` export can also initialize the database when the main files are absent. If a previously selected folder becomes unavailable, startup asks the user to choose it again rather than silently switching away from that folder's data.
- **Android item and image mirror:** every saved game is mirrored to `<app-key>-db/games/<item-id>/index.json`, including its description, provider identifiers, status, progress, cached provider details, and other item fields. The Add Game gallery and camera controls place picked cover bytes in app state; folder sync writes the cover and cached detail/gallery images as adjacent `.thumbnail` and `.image-*` files. Images are reduced to a maximum 500-pixel WebP when supported; each file's MIME type and the JSON paths it serves are recorded in `localImageFiles`. Inline image data is removed from portable JSON, including image data nested inside cached provider details, so the same bytes are not duplicated in JSON. If WebView cannot fetch a provider image because of CORS, the Android plugin downloads and downsizes it natively. Startup hydrates the cover for collection cards; details load their image files on demand. The central `database.json` is the collection index; each per-game `index.json` is the full portable game record and is written first, allowing startup to recover the latest item fields if a save was interrupted before the central index was updated. A `.nomedia` marker keeps Android gallery apps from indexing app artwork.
- **Folder traversal:** the Android SAF bridge accepts both the selected root URI and child-folder URIs when listing files. It uses the URI's current document ID so restore can descend from the database folder into the games directory and each game's image files.
- **Browser-only artwork:** when Android folder storage is unavailable, the localStorage mirror retains locally selected cover bytes so a browser reload does not lose them. Transient detail-gallery bytes are loaded from the folder when requested and are not duplicated into the browser mirror.
- **Timeline:** the timeline records status changes to Dropped, Completed, On Hold, Playing, and Upcoming. Other library edits and progress updates remain in activity history storage but are not shown as timeline events.
- **Android encryption:** `EncryptedStorePlugin` encrypts values with AES-GCM. API 23+ uses an AES key in Android Keystore; API 22 uses a randomly generated AES key wrapped by an RSA key held in Android Keystore.

The Android plugin encrypts native records, but the app continues to maintain a localStorage mirror and plain JSON databases in the user-selected folder. Neither should be treated as encrypted storage. Exported JSON and folder TAR backups are also plaintext unless protected separately by the user.

## Saved provider data

Opening a game's details, adding a metadata result, or using **Fetch details** on Statistics can save provider data in `cachedDetails` and a compact `facts` summary on the item. Sources can include HowLongToBeat completion targets, RAWG average hours, IGDB details, and other provider fields. On Android these are part of the saved item and are mirrored to native storage and, when selected, the folder `index.json`. With image storage enabled, cached detail artwork is copied into adjacent `.image-*` files for offline use. **Settings → Metadata & Storage** shows estimated library/cache usage and provides cache-clearing controls. Browser caching and Android folder image storage are separate mechanisms.

## Metadata cache

JSON GET metadata responses are stored in browser Cache Storage under `splitapp_savepoint_metadata`. Fresh cache entries are reused for six hours, and stale entries can be used after request failures unless the Offline Fallback preference is set to `none`. Requests with an API key in `key`/`apikey` query parameters, IGDB and HowLongToBeat POST searches, and HTML text requests are not cached by this JSON cache. See [metadata analysis](metadata-analysis.md).

## Backups and secrets

When `Backup Schedule` is set to Daily, changed data refreshes one `<app-key>_backup-YYYY-MM-DD.tar` snapshot in the selected folder. It contains the full `<app-key>-db` tree (central JSON database, per-game JSON records, and image files) plus a portable root JSON database copy. The configured retention count removes older SavePoint TAR and native `.sqdb` background snapshots. The native `.sqdb` format is an encrypted-state snapshot and does not include the separate folder image files.

JSON and `.sqx` transfer exports include preferences, which can contain configured API keys; treat them as sensitive. The `.sqx` transfer is password-encrypted; ordinary JSON and TAR folder snapshots are not. On Android, the import picker accepts `.sqx` and binary MIME files as well as JSON, gzip, TXT and CSV backups. **Encrypted transfer file → Create** opens Android's document picker; **Share encrypted transfer → Share** builds the file in bounded chunks and opens the system share chooser directly. Transfers include artwork already present in IndexedDB's saved image cache or the selected folder, and restore included image data, activity history and preferences. Cached image reads run in small parallel groups, reduced further on low-memory devices. Uncached images are not fetched during export. Native `.sqdb` background backups use a separate, device-bound format.

## Scope

The key and cache names are app-specific to SavePoint. This local storage model does not provide account sync or remote backup by itself. See [database analysis](database-analysis.md) for the data model and read/write sequence.


## Logcat and library history files (0.1.3)

Next to `games/`, `.nomedia` and `database.json`, `savepoint-db/` holds `logcat.json` and `library-history.json`: the full history, newest first (capped at 20,000 entries each). The device keeps only the latest 200 logcat entries and 400 history entries for quick display; the Logcat and Library history pages load the full files and can search all of it. Clear them from either page or from Settings → Storage ("Clear logcat", "Clear library history"), which empties the files too. Without a chosen storage folder, only the recent local copy exists.

Both pages also have **From** and **To** date pickers (inclusive, whole days) that combine with the text search; "Clear dates" resets them.

## Transfers: progress, notifications and images (0.1.10)

- `.sqx`/JSON imports report **bytes read** from the file while reading (`SplitAppBackupStream.parseFile(file, { onBytes })`), then count games saved and images cached. The same percentage drives the import page, the floating transfer button and the Android notification (`ShareIntent` plugin, `kind: "import"`).
- Export and import move a game's images concurrently (up to 4 per game; imports process 3 games at once, 2 on low-memory devices). Images travel inside the file as data URLs and are written back to the artwork cache by path.
- An ongoing export/import notification is cancelled when the activity is destroyed, swept on the next launch, and expires after two minutes without updates.
- Trailer links (`videos` sections: mp4, webm or HLS) are stored with the game in `cachedDetails`, so they remain available as fallback links offline.

## Achievements page performance (0.1.10)

- `entries()` caches its last result keyed by the library array, its length, the sum of `updatedAt` stamps and the favourite count; a changed library recomputes. The profile, the achievements page, award checks and shares all share that result.
- Badge placeholders are static (no `ach-shimmer` animation), `.ach-section` and grid tiles use `content-visibility:auto`, and badge images are `loading="lazy" decoding="async"`.

## Game details, RAWG and profile (0.2.0)

- RAWG details load up to 120 achievements (40 per page) and keep them in the game's `cachedDetails` (IndexedDB, like every other detail section). Games saved by an older version only held 8, so they are refreshed once when opened online. RAWG requests are spaced 0.15 s apart instead of the 1.2 s used for other hosts, because one game page needs several calls.
- API keys are entered only on a source's options page (`#settings/source-options?id=<source>`); the Metadata Sources list no longer shows key fields.
- Hidden profile sections are stored in `localStorage` as `savepoint_profile_hidden_sections` (an array of section keys); they are excluded from the profile page but stay in the reorder sheet.
- Quick Setup keeps a per-session cache of HowLongToBeat search results and cancels the previous request when you keep typing.
